Baseline Sharpe ≤ 0, so the Sharpe criterion is +0.1 absolute. All columns except the last two are from the
50,000 JPY run.

- **`equal-weight-subsignals-current-config` — rejected on drawdown alone, flagged for human review.**
  At 50k it cleared Sharpe (+1.27; −0.68 → +0.60) and trade count (4 vs 1), turned the return positive
  (+0.15%) and beat its static mix by +0.77 pp — but max DD rose 2.78% → 3.27%, so `compare` rejects it.
  At the diagnostic capitals it is **the best result this pipeline has recorded**: 500k Sharpe −28.53 →
  −4.94, return −14.96% → −2.80%, DD 15.26% → 4.13%, trades 800 → 108, fees 29,888 → 6,395 JPY; 5M
  −11.64% → −2.25%. It still loses to the static mix at 500k (−2.26 pp) and 5M (−1.71 pp). Sign flip across
  capitals: at 50k drawdown is worse, at 500k/5M every metric is better.
- **`trend-weight-half-current-config`** — at 50k both runs made only the opening buy, so the delta only
  measures the opening position size (exposure 0.538 vs 0.481). Not a verdict on the idea. At 500k/5M it
  roughly halves the loss (−7.26% / −5.42%).
- **`rebalance-spacing-15m-current-config`** — economically identical to baseline at 50k (lot floor). At
  500k/5M it improves Sharpe (−18.2 / −13.6) and cuts trades 800 → 376.

Taken with 2026-10-19's `trend-weight-half` and `trend-weighted-subsignals`, this is now four
variants across two runs on 1-minute bars in which **raising the trend weight improves the diagnostics
monotonically** (0.25 → 0.5 → 1.0 at 500k: −14.96% → −7.26% → −2.80%). The promotion rule cannot see it,
because at 50k the lot floor suppresses almost all trading.

**Worktrees.** Both algorithm variants touch `compute_btc_target`'s body, so per the routine's instructions
