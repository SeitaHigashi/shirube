### Enabling changes

None this run — no capability was added and no defect was fixed. Three
things were found and deliberately left alone:

- **`Simulator::run` hardcodes an empty news slice** (`src/backtest/simulator.rs:92`),
  so no variant can ever exercise a non-zero sentiment channel in backtest.
  Any hypothesis that raises `sentiment_weight` is measuring how much
  constant-0.5 dead weight it adds, not a real signal. Not a defect in the
  measurement of anything tried so far (today's `full-ta-weight-no-sentiment`
  sets the weight to *zero*, which is the one honest point in that space),
  but it means sentiment-weight sweeps are not meaningful under the current
  simulator. Wiring historical news into the simulator is a substantial
  capability addition and would have made today's numbers non-comparable to
  the baseline mid-run.
- **The `content_hash` serialization ambiguity** described under "Candidate
  filtering" above — four runs in a row have now re-derived it. A
  `shirube hypothesis-hash` subcommand would end it permanently.
- **A `NaN` hazard the promoted diff introduces and guards against**: the new
  damped crossover divides by the reference line, where the old step function
  only compared. A non-positive `sma`/`ema` would produce `NaN`, which
  `f64::clamp` propagates rather than clamping, silently poisoning
  `ta_normalized`. Unreachable on real BTC/JPY prices, but the failure would
  be silent, so the diff skips the sub-signal in that case. Called out in the
  PR for review rather than treated as settled.
