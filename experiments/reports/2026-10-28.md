## Enabling changes

- **[#35](https://github.com/SeitaHigashi/shirube/pull/35)**, branch `fix/cli-help-does-not-start-server`:
  - **Problem:** `shirube --help` fell through `cli::dispatch()` into full server startup (port 3000, bitFlyer WS, mock or live trading). Two of today's worktree agents hit it. Both ran in mock mode with no keys and placed no orders, but one server stayed up for several minutes.
  - **Fix:** `--help`, `-h` and `help` now print usage and exit. Other unknown arguments still start the server, because the auto-updater re-execs with the original argv. This touches startup and is flagged in the PR.
  - Regression tests added; 261 passed.
  - It does not affect any measurement.

Suspected defects, not fixed:
- The live `SignalEngine` has no rolling close history beyond the indicators, so features computed only in `compute_indicators()` (here `realized_vol`) are always `None` live. This is the same gap as noted before.
- The backtest treats a multi-minute gap between bars as one 1-minute return. About 24% of minutes have no trade, which slightly inflates any per-bar volatility estimate. This is minor.
- Still open from earlier runs: live `fee_pct()` hardcoded at 0.0015 (touches live trading); `Simulator::run` discards `send_order` errors; `-0.0` fees on zero-trade runs.
