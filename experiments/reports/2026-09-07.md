### New hypotheses generated this run
Both existing hypothesis files (`example-algorithm-change.json`,
`example-parameter-tuning.json`) match entries already in
`experiments/tried.json` by name/config/rationale (their content_hash
did not byte-for-byte match the registry's stored hash — the doc
doesn't pin an exact JSON serialization for the hash, so this is most
likely a hashing-implementation difference rather than a genuinely new
variant; treated as already-tried by content match rather than re-run).
`CANDIDATES` was therefore empty, triggering hypothesis generation:

- **shorter-hourly-indicator-periods** (parameter): `src/backtest/simulator.rs::Simulator::run`
  feeds `compute_indicators()` only the exact `[from,to]` slice with no
  pre-holdout warmup buffer. The default `sma_period=200` (hours) alone
  consumes ~60% of the 336-hour (14-day) holdout before SMA can return
  `Some`, and `ema_period=100`/`macd_slow=104`/`bollinger_period=60` eat
  deep into the same window — starving the holdout of active-signal
  candles regardless of market direction. Proposes standard hourly-scale
  periods (RSI 14, MACD 12/26/9, Bollinger 20, SMA 48, EMA 24).
- **lower-allocation-threshold** (parameter): isolates
  `allocation_threshold` (default 0.15, i.e. a 15pp gate before any
  rebalance fires) as an independent variable from indicator warmup,
  testing 0.05 with every indicator period left at default.
- **continuous-crossover-subsignals** (algorithm, touches
  `compute_btc_target`'s body per the 2026-09-08 policy change): the
  SMA-cross, EMA-cross, and MACD-histogram sub-signals in
  `src/trading/engine.rs` are hard step functions (0.0/0.5/1.0) with no
  magnitude awareness, making `ta_normalized` maximally sensitive to
  noise right at each crossover boundary. Proposes replacing them with a
  continuous, saturating (clamped) distance-based mapping instead.

All three passed the CLI's `TradingConfig::validate()` check (confirmed
via a `backtest-variant` dry-run against each config, which failed only
on "no candles found", never on "invalid trading config"). None were
backtested this run due to the data-bootstrap block above — they remain
in `experiments/hypotheses/` for the next successful run to pick up.
