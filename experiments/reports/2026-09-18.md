### `zone-damping-095` — rejected, and it is the run's most valuable result

The hypothesis asked for the conservative point on the band-width dose-response curve. It failed at
the promotion capital on Sharpe (−3.979 → −12.989) and drawdown (+2.76pp), and — against the entire
premise of a *gentler* damping — it more than doubled the trade count (66 → 142) and nearly doubled
fees (1,133 → 2,196 JPY). At the two diagnostic capitals the same config improves every metric
(500,000 JPY: Sharpe −26.626 → −24.328; 5,000,000 JPY: −19.977 → −18.349).

The agent did not file that as "×0.95 damping is bad". It swept the factor at the promotion capital
instead:

**×0.95 is an isolated spike, not a point on a curve.** Its immediate neighbours are 2.5–3.2× better
on Sharpe, and ×0.93/×0.97/×0.98 all beat the baseline. The same sweep at 500,000 JPY, where the lot
floor is inert, is smooth and monotone (×0.96 → −24.899, ×0.95 → −24.328, ×0.94 → −23.784).

The mechanism is the doc's lot-size floor in a **second, previously undocumented form**. At
50,000 JPY one 0.001 BTC lot is ~26% of the portfolio; of ~5,900–6,500 evaluations that clear
`allocation_threshold`, only 66–142 ever produce an executable order, and each one that does executes
a ~26% jump in exposure that re-seeds `current_alloc` and therefore the entire subsequent path. The
system is path-dependent and effectively chaotic there: an infinitesimal shift in the target curve
changes *which* evaluations cross the lot boundary, and the trajectory diverges. The doc currently
warns only about the *false-negative* case (a sub-0.245 `allocation_threshold` producing identical
reports). The dangerous case is this one, where the report is wildly *different* for no economic
reason, in either direction.

**Two disciplines this imposes, recorded so they are not lost.** First, the sweep above was measured
**on the holdout window**, so its specific values are diagnostic only — picking tomorrow's dose from
this table would be exactly the overfitting the holdout split exists to prevent, and the doc's rule
that a variant may only be *authored* from pre-holdout data still binds. What transfers is the
*structural* finding (the primary capital is chaotic for this family), which is a property of the
measurement, not of a parameter value. Second, every verdict this pipeline has ever recorded for a
continuous-target parameter hypothesis at 50,000 JPY carries an error bar that `compare-backtest`
does not print.

### `hourly-rebalance-spacing` — promoted, and it reframes PR #26

Raising the existing `rebalance_interval_secs` to 3600 cleared all three criteria: Sharpe
−3.979 → −1.034, drawdown 7.04% → 4.16%, 33 trades — **exactly on** the 0.50 trade-count floor.
Fees fell 46.6% at the primary capital (1,133 → 604 JPY) on 49.6% less turnover, and every metric
improves at all three capitals (500,000 JPY: Sharpe −26.626 → −8.236; 5,000,000 JPY:
−19.977 → −5.956, both on 150 trades against 807).

Its purpose was to test yesterday's observation that `h1-block-held-signal` (PR #26, a new
`signal_block_secs` code path) fired 39 of its 40 trades on block boundaries and so looked
"nearly indistinguishable from an hourly action throttle". The answer: **an hourly throttle does
clear the promotion bar with zero source change** — but the agent measured that the two mechanisms
are not the same thing, rather than assuming it:

- **Composite freshness.** `rebalance_interval_secs` gates only the allocation-delta evaluation;
  `compute_btc_target`, the `sticky_target` update and the circuit-breaker check still run every
  candle, so an evaluation acts on the *current* composite. `signal_block_secs` freezes the composite
  for the whole block, so it acts on a value up to 59 minutes stale.
- **Phase.** The spacing clock is anchored to the last *evaluated* candle
  (`candle.open_time - prev >= rebalance_interval`), not to a UTC grid. Of 334 evaluations, only
  **20 landed on `:00`**, spread over 45 distinct minute offsets, and 80 of 333 inter-evaluation gaps
  exceeded 3600s because a missing candle at a grid point pushes the whole downstream schedule forward
  permanently. `rebalance_interval_secs: N` means "at least N seconds apart", never "on an N-second
  UTC grid".

So PR #26 is not made redundant, but its reviewer now knows a zero-code config change clears the same
bar on the same window. Part of the primary-capital gain is explicitly a floor interaction
(`orders_below_min` 5,791 → 164: with 334 evaluations instead of 15,265 there are far fewer chances to
be dropped, and each surviving delta has had an hour to accumulate past the lot); the sign holds at the
two capitals where the floor is inert, so the direction is not a floor artifact even though the
magnitude is floor-assisted.

### `zone-damping-090` — promoted, with the identity verified to 1.9e-8

The band 0.0555556/0.9444444 was verified **empirically, not assumed**, to be exactly an ×0.90
compression of the baseline's allocation target about neutral: over the 15,265 evaluated candles
`max |variant_target − (0.5 + 0.90·(baseline_target − 0.5))| = 1.881e-8`, the residual being the
config's 7-decimal rounding (realised slope 1.1250001 rather than 1.125 — the schema cannot express
1/18 and 17/18 exactly). Neither saturation arm was hit on any candle for either config (realised raw
composite band [0.337561, 0.667219], mean 0.500432, sd 0.074452, both midpoints exactly 0.5), and the
composite series was identical under both configs on all 15,265 candles — so the zone is provably the
only thing that moved. Both damping agents independently reproduced that same composite band to six
decimal places.

It is the **first dose on this curve to clear `MIN_TRADE_COUNT_RATIO`**. The prior bracket was measured
on *yesterday's* window (baseline 76 trades): ×0.80 → 10 trades and ×0.75 → 1, both of which died on
trade count alone while passing Sharpe — so the doses are comparable in shape but not in absolute
counts with today's 66-trade baseline. Fees fell at
every capital (−31.7% / −16.6% / −16.7%), with `effective_fee_pct` *rising* 3.8–6.6% as the account
drops a commission tier — the doc's sublinearity caveat, reproduced for the third run running, and
still standing on `MockExchangeClient`'s from-zero, never-expiring volume accumulator.

One honest qualification the agent raised itself: at 50,000 JPY `orders_below_min` **rose**
5,791 → 6,566, because a damped target makes each per-candle delta smaller and more of them die under
the lot. The lot floor is therefore acting as a second, implicit damper stacked on the configured one,
and the effective damping at the promotion capital is not purely ×0.90.

### Suspected defects found and deliberately not fixed

- **The promotion capital is not a stable estimator for continuous-target hypotheses. NEW this run,
  and the most consequential thing on this list.** Measured: a 1pp change in target amplitude swings
  the 50,000 JPY Sharpe by ~3× non-monotonically, while the identical sweep at 500,000 JPY is smooth
  (full table above). Not "fixed", because every remedy changes the promotion rule and that is a human
  decision. Three options, cheapest first: (1) report a jitter band — re-run each variant at ±1% of its
  parameter and print the spread, so a verdict carries an error bar; (2) keep deciding at 50,000 JPY
  but require the *sign* of the effect to agree at 500,000 JPY before writing a verdict to
  `tried.json` (today's two promotions pass this; the rejection fails it, which is the point);
  (3) report `orders_below_min / (orders_below_min + total_trades)` as a ratio — 98.9% baseline today
  — so a reader sees immediately how much of the strategy is being discarded at that capital.
- **`backtest-variant` has no per-trade or equity-curve export.** This blocked the inter-trade gap
  distribution `hourly-rebalance-spacing` was asked for (the agent reported the bound it could
  establish — every gap ≥3600s, mean ~10.5h — rather than guessing). A `--trades-out <path>` flag
  would make turnover-shaped hypotheses directly verifiable. **NEW this run**; a clean candidate for
  its own enabling PR, deliberately not done mid-run so a `kind: "parameter"` result stayed clean.
- **`rebalance_interval_secs` is a drifting spacing, not a grid.** Because the anchor is the last
  evaluated candle, every data gap permanently shifts the whole downstream schedule (measured: 80 of
  333 gaps > 3600s; evaluations spread over 45 distinct minute offsets). This faithfully mirrors the
  live engine's periodic-ticker semantics and the in-source NOTE intends it, so it is behaviour and not
  a bug — but anyone comparing it against a UTC-aligned block mechanism must know. **NEW this run.**
- **The config schema cannot express a rational damping factor exactly.** `apply_zone`'s slope is
  `1/(hold_btc_above − hold_jpy_below)`, so 1/18 and 17/18 round to ×0.90000009. Measured effect
  1.9e-8 of allocation; irrelevant to any result, relevant only if doses are ever compared beyond ~7
  significant figures. **NEW this run.**
- **`backtest-variant` writes to the DB it is documented as reading** (`backtest_runs` insert on every
  run). Carried from 2026-09-17; unchanged and still harmless (the file grew by 8KB across nine runs
  today).
- **`sharpe_minus_static_mix` is not a like-for-like delta between rows** — the static-mix benchmark is
  rebuilt at each run's own `avg_btc_exposure`. Carried from 2026-09-17; stated again in both PRs.
